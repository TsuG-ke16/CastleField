# 4陣営（ベータ）— 先行プレイ版

4陣営モードのベータ版。**入口はホームの「4陣営モード」に一本化した**（#192 のホームに合わせた。人間の指示）。ひとりで遊ぶ（CPU）・カジュアル対戦（合言葉の部屋）・同じ端末で遊べる。**カードの数値・効果は #178 の確定仕様のまま変えていない**（バランスは `balance-proposal.md` に提案としてまとめた）。

## 遊び方（アクセス方法）

1. オンラインで遊ぶときは、リポジトリのルートで `node server/server.js`（既定ポート 8787。`PORT` で変更）を起動し、`http://<サーバー>:8787/` を開く（ひとりで遊ぶ・同じ端末だけなら `python3 -m http.server` でもよい）
2. ホームの上の「通常モード／4陣営モード」で **4陣営モード** を選ぶ（`?mode=factions` で開いても同じ。前の入口 `?beta=factions` も同じ扱い）
3. 「使用する陣営」で陣営を選ぶ（王国・森の同盟・魔族軍・竜族帝国）
4. 対戦形式で遊び方を選んで「対戦の準備へ」
   - ひとりで遊ぶ：CPU の強さを選ぶ。相手の陣営は自分と別の陣営になる
   - カジュアル対戦：同じ合言葉を入れて「部屋に入る」。ホームで選んだ陣営が自分の席の陣営になる。部屋の「陣営」で変えられ、相手の選択もすぐ画面に出る。「陣営の説明」で各陣営の説明と全カード（絵・MP・枚数・効果）が見られる。部屋主が「対戦をはじめる」。決着後は「もう1回」（同じ陣営で再戦）か「部屋に戻る」（陣営を変えられる）
   - 同じ端末：2〜8人で交代

選んだモードはこの端末に覚える（`cf-home-ruleset`）。次に開いたときも4陣営のまま。ただし `?debug=1`・`?local=1`・`?seed=` で開いたときは覚えたモードを使わず、URL の `?mode=` だけを見る（なければ通常モード）。ページを読み直したときに入っていた部屋が残っていれば、**その部屋のモード**でつなぎ直す（通常モードの部屋を4陣営で開くことはない）。

## 通常モードとの分離

- 入口はホームの「4陣営モード」（だれでも選べる。前のような URL を知っている人だけの限定公開ではない）。
- **ランク戦・ランキング・フレンド・ミッションは4陣営では使えない**（ホームで押すと「通常モードで利用できます」と出す）。
- **オンライン対戦の戦績・経験値・コイン・ミッションに記録しない**：`data/modes.json` の `beta: true` のモードは、`Room.finishMatch` が `onMatchEnd` を呼ばない（`tests/factions-server.test.js` で確認）。
- 4陣営のときは、ひとりで遊ぶでもチュートリアルを出さない。`?debug=1` は覚えたモードを使わないので、4陣営をデバッグするときは `?debug=1&mode=factions`。
- 部屋と対戦の画面左上に「4陣営（ベータ）」の目印（ホームは「4陣営モード」と出ているので出さない）。部屋にも「結果は記録されません」と出す。
- 通常モード・クラシックのコード・データ（`js/game/`、`data/cards.json`、`data/rules.json`、`data/classic/`）は変えていない。

## 既知の不具合・未実装

- 部屋に CPU を足すことはサーバー側でできるが、画面の「部屋の CPU 追加」の確認は不十分。
- 演出は最小限：属性反応は名前＋属性アイコンの表示と画面の揺れだけ。専用エフェクト・効果音なし。血の膜・城の身代わり・回復減少は常時バッジではなく、起きたときの表示のみ。
- カードは陣営のフレーム（手札・陣営の説明・効果の演出）。「陣営の説明」のカードを長押しすると、陣営の3Dフレーム（Blender 製の `card-faction-*.glb`）で拡大する（`ui-tests/faction-beta-cards.js`）。手札のカードは通常モードと同じく長押しで拡大しない（手札の長押し拡大と、3Dカードのこれ以上の作り込みは、今はやらない。人間の指示）。
- 部屋の「ルールを変更」にある項目のうち、4陣営で意味のないもの（山札の形・チーム）は隠したが、「ステージ」「城のHP」は選べる。
- 4人以上・チーム戦は断る（サーバー仕様）。2人対戦のみ確認。広場（3人以上）の画面は未検証。
- 森の同盟が弱い・試合が長い（`balance-proposal.md`）。魔物の放置で城が落ちて決着する試合が多い。
- 本番公開の前に決めること：`available:false` のモードに `mode` 指定で入れる問題（#182 の「人間が決めること」①）は、ベータの試合を記録しないことで影響を止めたが、入口を閉じる仕組み（環境変数など）は入れていない。
