# オンラインスキルの安全な実行・表示

基準: PR #203 `12ff43b786959a28d8afd5fbf25367e96d2438ce`（PR #202最新 `ba3b524` を含む）。新しい画面・ナビ・ガチャ/ショップ/スキンの変更はなく、既存の戦闘中スキルパネルとカード使用前の選択欄に統合する。

## 公開と実行権限

- OnlineClientの任意スキルを既存Game.skillActionへ接続。実行者IDはRoomが認証済みの席から付け、クライアントの引数で他人に差し替えられない。
- setSkillPrefsも席本人の設定だけ。未取得ノード・不明な値はRuntimeの既存スキーマで拒否する。
- previewSkillCostは本人の手番・メイン行動中・本人の手札だけを対象にする読み取り専用操作。Gameの同じ費用計画を返す。支払い・履歴・乱数・CPU進行・状態配信は行わない。
- 相手のスキル発動は名前＋公開済みの定義文で表示。城回復/城壁変化の公開効果も記録する。
- 生のskillEventsを送らず、Runtime.logForでkind/turn/playerId/skillId/countと許可した城効果の種類/量だけを抽出する。診断は本人だけにcodeを送る。手札ID・山札・peek・選択引数・一時コピー・内部エラーメッセージ・設定値をログに混ぜない。相手の兵士に関する効果の内部記録も送らない。

## 失敗時の整合性

任意スキルとスキル付きカードの実行をトランザクションで包む。

1. 現在の可変エンジン状態をオブジェクト参照を保ったまま記録。
2. 実行中は外部のGameイベント購読・スキルログ購読への通知を保留。内部の効果処理は通常どおり進める。
3. 明示的なfalse/ok:false、例外、下流ハンドラのhandlerErrorではHP/MP/資源・手札/山札・兵士/城・回数/カウンタ・予約/キュー・ログを復元し、保留通知を捨てる。
4. 失敗時に取得した乱数値は次の取得で再利用し、失敗の再試行で乱数列を進めない。成功時だけ確定通知を渡す。

ゲームのルール、価格、スキルの威力や条件は変えていない。通常/4陣営などスキルRuntimeのないゲームにはこの処理を追加しない。スナップショットは保存ファイルではなく同期実行中だけ保持する。

## 既存パネル・ログ

- スキルパネル内「自動発動の設定」に、既存のX35.autoDefer（任意HP支払いの自動延期）とX15.pick（先頭2枚からの選択）を追加。取得したものだけ表示し、設定値は本人だけが受け取る。新しい自動発動ルールや全スキル一括無効化は追加しない。
- 発動ログはオンラインでも表示。毎回のgetStateの公開履歴から再構成し、起動前のイベント購読漏れや再描画/再接続で消さない。送信は直近100件、既存パネルは直近40件を表示する。
- Roomが状態へmatchIdを付け、再戦は同じターン数でも新試合として認識する。旧試合の遅延した勝敗表示も世代と現在phaseで破棄する。
- カード費用確認は非同期サーバー応答待ちの間「使う」を無効化。選択を変更した場合は古い応答を無視。通信失敗/費用不足では確定できず、キャンセルでは操作を送らない。
- 試合/手番/手札/セッションが変わった場合、未確定の費用選択を破棄する。
