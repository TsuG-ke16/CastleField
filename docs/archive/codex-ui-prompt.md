# Codex への依頼：キャッスルフィールドの演出とデザイン（UI担当）

あなたはブラウザカードゲーム「キャッスルフィールド」の **画面（UI）の演出とデザイン** を担当します。
ゲームロジック側の変更（PR「feature/card-rarity」）がすでに入っているので、その新機能を画面で使えるようにしてください。

## 最初にやること

1. リポジトリのルートの `CLAUDE.md` を**最後まで読む**（仕様の正です。「ロジックとUIの約束」「カードのレアリティと合成」「コインの入手手段を増やした」「魔物は放置するとヤバい・倒すとドパが出る」の節が今回の変更）。
2. ブランチを作る：`feature/ui-rarity-fx`（main には直接コミットしない）。作業前に `git pull origin main`（PR がマージ済みなら）か、`feature/card-rarity` を取り込む。
3. 起動：`python3 -m http.server` → `http://localhost:8000`（ひとりで遊ぶ：`?local=1&cpu=hard`、デバッグ：`?debug=1`）。オンラインは `node server/server.js`（`http://localhost:8787`）。
4. 自動テスト：`node --test`（全部通ること）。

## 触っていい範囲

- 触る：`index.html`、`css/`、`js/ui/`、`js/main.js`、`assets/`
- **触らない**：`js/game/`、`data/`、`tests/`、`server/`、`CLAUDE.md`（共有）。ロジックや数値を変えたくなったら、変更せずに PR の説明文に「相手側で必要な変更」として書く
- UIは**ゲームの状態を直接書き換えない**。必ず Game のメソッド（オンラインならクライアント越し）を呼ぶ
- 数値・説明文は `data/*.json` から読む。コードに数値を直接書かない
- 外部パッケージは使わない（フレームワークなし、ES Modules）

## ゲームの前提（変わった点）

- カードに**レアリティ**（コモン・アンコモン・レア・エピック・レジェンド。`data/rarities.json`：`name`・`dropRate`・`color`）。カードは `cards.json` の `rarity`、合成先は `fuseTo`
- 手札の**同じ種類のカード2枚を合成**して、1つ上のレアリティの別のカードにできる（`game.canFuse(a, b)` / `game.fuse(a, b)`。メインの1枚には数えない。レジェンドは合成不可。オンラインは `POST /api/action` の `method: "fuse"`、`args: [cardIdA, cardIdB]`）
- **コイン**：最初に5枚、自分のターンの始めに+1、コインのカード（小銭袋→金貨→財宝→金脈→王の財宝）で増える。`coinsChanged.reason` は `"reward"` / `"upgrade"` / `"turn"` / `"card"`
- **コインで買う強化**（`data/upgrades.json`、`game.canBuyUpgrade` / `game.buyUpgrade`）：修理系・補充系・とぎ石系・運命の祈り（`luck`）・**入手券**（コモン〜レジェンド）・**訓練 / 猛特訓 / 鍛錬 / 超鍛錬**（兵士をずっと強化）。`getState().players.pX` に `coins` / `luck` / `armyAttack` / `armyHp`
- **魔物のごほうびはカード**（`monsters.json` の `rewardRarity`）。倒すと、そのレアリティのカードが1枚、とどめを刺した人の手札に入る。確率で**ラッキー**（1つ上のレアリティ）
- **魔物は放置するほど攻撃が重くなる**（城を攻めるたびにダメージが増える）。`getState().monsters[]` の `castleAttack` は「次に攻めるときのダメージ」、`attackIn` は「あと何周で攻めるか」
- 魔物は全12種になった。ドローは「出した枚数ぶん」引く。城HP上限は70（先攻・後攻同じ）

## 今回の主役：2つの「ドパ（快感）」

この遊びで大事にしたい要素です。**ここにいちばん力を入れてください**。

### A. 魔物を放置するとヤバい（恐怖が見える）

- 魔物のそばに、**次に城へ与えるダメージ**（`castleAttack`）と**あと何周か**（`attackIn`）を、一目で分かる大きさで出す。攻めるたびにダメージが増えるので、数字が増えていくのが見えるようにする
- `attackIn` が1以下（次の周回で攻めてくる）のときは、赤く脈打つなどの強い警告にする
- `monsterAttackedCastle` が来たら、魔物が城に襲いかかる演出：ヒットストップ → 画面を揺らす → 数字を大きく出す。**ダメージが大きいほど、止める時間・揺れ・音を大きく**
- 城HPが少ない状態で攻撃が近いときは、自分の城に「危険」表示

### B. 魔物を倒すとドパが出る（ごほうびの演出）

イベントの流れ：`monsterDefeated`（`rewardRarity` = 実際に出たレアリティ、`baseRarity` = 本来のレアリティ、`lucky` = ラッキーか）→ `cardDrawn`（`cardIds`。本人だけ。相手には `count`）。

- 魔物が倒れる演出 → ごほうびのカードがドンと出てくる**カード公開の演出**
- 演出の大きさは**レアリティに比例**（`rarities.json` の `color` を使う）。コモンはさっと、レジェンドは画面全体が光る
- **`lucky: true` のときは特別な演出**（「ラッキー！」の文字、レアリティが1段上がる見せ方）。ガチャの当たりのように派手に
- 勝った人を派手に褒める。**ただし演出はタップで飛ばせる**（長くしない。1回の演出は目安で2秒以内）
- 相手が倒したときは、手札の中身は見せない（枚数だけ。`cardDrawn` に `cardIds` は来ない）。演出は「相手がレアリティ◯◯を手に入れた」程度に（レアリティは `monsterDefeated` で全員に見える）

## やること一覧

### 0. 【最優先】今の使いにくさ（実際に遊んだ人の指摘）

遊んだ人から、次の3つを直してほしいと言われています。演出より先に直してください。

**0-1. カードを押しても情報が出ない／分かりにくい**
- カードをタップしたときの説明（`#card-detail`、`HandView.js` の `select()`）が、何のカードか分からないことがある。原因の1つは、`js/ui/text.js` の `cardDescription()` が、新しい効果の説明文を作れず空になること。**データ側（`data/cards.json` の `description`）は、コインのカードに足し済み**。それでも空になるカードがないか、全69種を `?debug=1` で手札に出して確かめる
- タップしたら、必ず次を出す：**名前・レアリティ（色つき）・種類・効果の説明・出せない理由（あれば）・合成先（`fuseTo`）・排出率**。長押し・クリックのどちらでも出る。タップして何も起きない状態を作らない
- 説明文が空のとき（新しい `effect` を足したとき）に気づけるよう、開発時は `console.warn` を出す

**0-2. コインで買う強化が縦に長く並んで見づらい**
- 強化は今 18 種類（`data/upgrades.json`）。縦1列の長いリストをやめる。カテゴリのタブ（回復・補充・強化（兵士）・入手券・特殊）＋グリッド（カード型のタイル）にする
- 1つのタイルに：名前・効果（`description`／`upgradeDescription()`）・値段・残り回数（`limit` − 買った回数）・買えない理由。買える物は光らせ、買えない物は暗くして理由を見せる
- 入手券は、レアリティの色つきで横に並べる（コモン〜レジェンド）。スマホ縦画面で、スクロールが短くなるようにする
- `upgrades.json` の `description` が空の強化は、`text.js` の `UPGRADE_TEXT` に型を足す（今は `repairCastle` / `drawCards` / `sharpenSoldiers` だけ。新しい効果は `boostDrops` / `gainCard` / `trainArmy` / `fortifyArmy`）

**0-3. カード一覧の画面がない**
- **どの画面からでも開ける「カード一覧」**を作る：タイトル・メニュー・ゲーム中（メニューから、または手札の横のボタン）。ゲーム中に開いても、ゲームは止まらない／進まない（自分の番を邪魔しない）
- 全69枚を、レアリティごと（コモン〜レジェンド）に並べて見せる。カードは絵・名前・レアリティの枠色・簡単な数字（`cardShort()`）。タップすると詳しい説明
- 絞り込み：レアリティ、種類（兵士・魔法・武器・防御）。検索は任意
- 各カードに：効果の説明・排出率（`dropRates()` in `js/game/Setup.js`）・合成の流れ（`fuseTo` をたどって「歩兵 → 重装兵 → 騎士 → 巨人 → 勇者」のように系統を表示）
- 同じ画面に、**魔物の一覧**（HP・攻撃・属性・放置ダメージ・ごほうびのレアリティとラッキー込みの内訳）と、**排出率**のタブも置く（後述の「排出率を見られる画面」と同じ画面にまとめてよい）
- ゲームのデータは `data/cards.json`・`rarities.json`・`monsters.json`・`upgrades.json` を読む（コードに数値を書かない）。オンラインでも、これらのファイルは配信されている

### 1. レアリティの見た目
- カードの枠・色・名前を、レアリティごとに変える（`rarities.json` の `color`、`name`）。見て分かる強さの違い（枠の豪華さ、光り方）
- レジェンドは特別（常に光る、など）
- 絵柄は `assets/STYLE.md` の共通の指示文に従う

### 2. 合成の操作
- 手札の同じ種類のカードが2枚あるとき、合成できると分かる表示（光る、バッジ）。タップ操作は短く（例：片方を長押し／ドラッグで重ねる／「合成」ボタン）
- 合成の演出：2枚がぶつかって光り、上のレアリティのカードに変わる（`cardsFused`：`{ playerId, cardIds, cardId, from, to }`）。相手には `{ playerId }` だけ届く
- 合成できない理由は表示する（`canFuse` の `reason`。オンラインはカードの種類から画面側で判定してよい）。押して何も起きない操作を作らない

### 3. コインと購入（ショップ）
- 自分のコインを常に表示。コインが増えるときは `coinsChanged` の `reason` ごとに軽い演出（`"turn"` は小さく、`"card"` は大きく）
- 強化の購入画面：`upgrades.json` の全項目を、効果の説明（`effect` と数値から組み立てる）・値段・残り回数（`limit`）・買えない理由つきで一覧表示。入手券と訓練系は種類が多いので、カテゴリに分ける
- 運命の祈りが効いているときは、「あと◯枚」のバッジ（`players.pX.luck`）。訓練・鍛錬で上がった分は、兵士の攻撃力・HP表示に反映（`armyAttack` / `armyHp` は合計の表示用）
- 兵士が強化されたときの演出（`soldierBuffed`：`attack`、鍛錬のときは `hp` も）

### 4. 排出率を見られる画面
- 「排出率」ボタンから開く画面：レアリティごとの割合、カードごとの割合、魔物のごほうびの内訳（ラッキー込み）
- ローカルでは `game.getDropRates()` が返す `{ rarities, cards, monsters }` を使う。オンラインではブラウザに Game がないので、`js/game/Setup.js` の `dropRates()` / `rewardOdds()` を import して、`data/cards.json`・`data/rarities.json`・`data/monsters.json`・`data/rules.json` の `rewardLuckyChance` から画面側で計算する（ES Modules でそのまま読める）
- 参考：`node tests/sim/droprates.js` で同じ内容が表で出る

### 5. 新しい絵（assets）

**新カード**（`js/ui/art.js` の `CARD_ART` に同じキーで足す。絵がなければ名前の1文字目の仮の絵になる）：
- 兵士：`hero`（勇者）
- 城攻め魔法：`inferno`、`starfall`、`apocalypse`
- 対兵士魔法：`raijin`、`judgment`
- 回復：`greatHeal`、`holyLight`、`goddess`
- 毒・氷：`deathMist`、`plague`、`absoluteZero`、`frozenWorld`
- 武器：`magicSword`、`holySword`、`godSword`
- 盾：`steelShield`、`holyShield`、`godShield`
- 城壁：`stoneWall`、`gate`、`barrier`
- 精霊王：`fireKing`、`waterKing`、`windKing`、`earthKing`
- コイン：`coinPouch`、`goldCoin`、`treasure`、`goldVein`、`kingTreasure`

**新しい魔物**（`MONSTER_ART` に足す）：`ghost`、`treant`、`mimic`、`vampire`、`demonKing`（魔王はいちばん迫力のある絵に。レジェンドのごほうび）

**既存の魔物**：`bat`、`slime`、`goblin`、`skeleton`、`golem`、`demon`、`dragon`

- 画像のルール（`CLAUDE.md`「画像素材」）：背景透明の PNG、カードの絵 512×512、魔物・兵士 256×256、1枚300KB以下、ファイル名は小文字の英字とハイフン（`cards/card-<type>.png`）
- 絵柄は `assets/STYLE.md` の共通の指示文を**毎回付けて**生成する（明るいカートゥーン調・太めのこげ茶の輪郭線・2頭身のちびキャラ）
- **出どころを `assets/CREDITS.md` に記録する**（ファイル名・作った道具・ライセンス・作った日）。再配布が禁止されている素材は入れない
- 全部を一度に作らなくてよい。まず魔物と、レジェンド・エピックのカードを優先（強さが一目で伝わるため）

### 6. 接続（js/main.js）
- ローカル（ひとりで遊ぶ・同じ端末）で `new Game(...)` を作るときに、`rarities`（`data/rarities.json`）と `upgrades`・`monsters` を渡す（渡さないとレアリティ・入手券・魔物のごほうびが動かない）。オンラインはサーバーが渡すので不要
- オンラインのクライアントに `fuse` を足す（`POST /api/action` の `method: "fuse"`）
- **CPUの強さ**：`CPU_LEVELS` の見直しが必要。先攻のとき random に勝つ割合は、今 rush（かんたん）42%・defensive（ふつう）19%・smart（つよい）97%で、「ふつう」が「かんたん」より弱い。`node tests/sim/run.js --match rush,random`（`defensive,random`、`smart,random`）で確かめて、強さの順になるように割り当てを直す（戦い方 `js/game/strategies.js` は触らず、PR の説明文に提案を書く）

## 守ること（ゲームづくりの原則）

- 迷ったら「遊ぶ人が楽しいか」で決める
- **演出は短く、タップで飛ばせる**。長い演出で待たせない（目安：1つ2秒以内）
- 攻撃が当たったら、ヒットストップ・画面の揺れ・数字を大きく出す、をセットで入れる。強い攻撃ほど大きく
- 押して何も起きない操作を作らない。出せない・買えない・合成できないときは、理由を表示する
- スマホの縦画面が基準。PCのブラウザでも崩れないようにする
- ブラウザのコンソールにエラーを出さない
- イベントはキューにためて、順番に演出する（イベントは操作の中で同期的に、起きた順に来る）
- 初めて見た人が説明なしで分かる見た目にする

## 出す前の確認

1. `node --test` が全部通る
2. ブラウザで、ひとりで遊ぶ（`?local=1&cpu=hard`）を最後まで遊ぶ。魔物の放置の恐怖、魔物を倒したときのごほうび（ラッキー含む）、合成、コインの購入、排出率の画面を実際に見て確かめる（`?debug=1` で手札や城HPを変えて試すとよい）
3. スマホ幅（縦）とPC幅で崩れていないか
4. PR を作る（`feature/ui-rarity-fx` → `main`）。説明文に「何を変えたか」「確かめたこと」「相手側（ロジック担当）で必要な変更」を書く。**自分でマージしない**（相手の承認を受けてからマージ）
