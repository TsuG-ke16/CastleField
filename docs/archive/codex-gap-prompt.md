# Codex への依頼：キャッスルフィールドの「足りないもの」を全部作る（UI担当）

あなたはブラウザカードゲーム「キャッスルフィールド」の **画面（UI）担当** です。
ロジック側（新兵士20体・部屋・広場・チーム戦など）は PR #47〜#53 で入っています。**画面側にまだ足りないものを、下の一覧すべて作ってください。** 大きいので、1つ1つ別のPRに分けます（1PR＝1機能。CLAUDE.md の決まり）。

## 最初にやること

1. リポジトリのルートの `CLAUDE.md` を**最後まで読む**（仕様の正。特に「チーム開発のルール」「ゲームづくりの原則（桜井流）」「ロジックとUIの約束」「画像素材」）。
2. 土台のブランチを決める。**PR #53（`feature/ui-step5`）が main にマージされていなければ、`claude/sweet-euler-e32tnv` から作る**（#47〜#53 と、読み込み画面・デッキ調整を含む）。マージ済みなら `git pull origin main` から。ブランチ名は `feature/<内容>`。main に直接コミットしない。
3. 起動：`python3 -m http.server` → `http://localhost:8000`。ひとりで遊ぶ：`?local=1&cpu=hard`、デバッグ：`?debug=1`。オンラインは `node server/server.js`（8787）。
4. 自動テスト：`node --test`（全部通ること）。画面は Playwright 同梱の Chromium（390×844）で必ず自分の目で確かめ、スクリーンショットをPRに貼る。

## 触っていい範囲

- 触る：`index.html`、`css/`、`js/ui/`、`js/main.js`、`assets/`
- **触らない**：`js/game/`、`data/`、`tests/`、`server/`、`CLAUDE.md`。ロジックや数値を変えたくなったら変更せず、PRの説明文に「相手側（ロジック担当）で必要な変更」と書く
- UIはゲームの状態を直接書き換えない。必ず Game のメソッド（オンラインならクライアント越し）を呼ぶ
- 数値・文言はできるだけ `js/ui/config.js` か `data/*.json` から読む。外部パッケージは使わない（ES Modules）
- 新しい画像・音は `assets/STYLE.md` の共通指示文で作り、同じPRで `assets/CREDITS.md` に出どころ・ライセンス・日付を書く。1枚300KB以下

## 共通の原則（桜井流。どのPRでも守る）

- 迷ったら「遊ぶ人が楽しいか」。押して何も起きない操作を作らない（出せない理由を出す）
- 演出はタップで飛ばせる。1回の演出は目安2秒以内。待ち時間を短く
- 初めての人が説明なしで触れるように。作った本人は慣れているので、分かりにくさは「思ったより下げて」考える
- 動かすたびに `?local=1&cpu=hard` で1試合通して遊び、コンソールにエラーが出ないことを確かめる

## やること一覧（優先順）

### 1. 初めての人のための案内（チュートリアル）【最優先】
今は「遊び方」の文章があるだけで、初めての人は何をすればいいか分からない。
- 初回起動（`localStorage` に済みの印がなければ）、「ひとりで遊ぶ」の最初の1試合の中で、**操作を1つずつ案内する**：カードをタップ→説明→レーンを選んで兵士を出す→ターン終了→兵士が進む→魔物が出たら…。1回の説明は1〜2行、「スキップ」をいつでも押せる
- 実際のカード・盤面を使う（ロジックは本物の Game。デバッグ用の `debugSetHand` は使ってよいが `?debug=1` でなくても動かせるか、使えないなら案内の手札は通常の配りで作る）
- 「遊び方」から、いつでも見直せる
- 完成の目安：説明なしの人が、最初の1分で兵士を1体出して、進軍が見られる

### 2. 設定画面（音・演出・見やすさ）
- タイトルとメニューから開く。`localStorage` に覚える（読み書きは try/catch）
- 効果音・BGM の音量（別々のスライダー）、演出の速さ（`UI_CONFIG.speed`：ふつう／はやい／スキップ）、動きを減らす（OSの `prefers-reduced-motion` を初期値にし、揺れ・点滅・ヒットストップを止める）、文字の大きさ（3段階）、名前
- 完成の目安：設定を変えて読み直しても残る。「動きを減らす」でも勝敗の情報が欠けない

### 3. BGM と効果音の充実
今は `js/ui/Sound.js` の合成音だけで、BGMがない。
- タイトル・戦闘・魔物が出ている間（緊迫）・勝利・敗北の BGM。外部ファイルを使うなら、**再配布できるライセンス**（CC0 など）だけを使い、`CREDITS.md` に出どころを書く。使えるものがなければ WebAudio で作ってループさせる
- 効果音は、攻撃の強さに応じて大きく／重く（桜井流：強い攻撃ほど止める時間・揺れ・音を大きく）。足りない音を洗い出して足す（弓・魔法弾・合成・ラッキー報酬・城が壊れる・ターン開始・カードを引く）
- 最初のタップまで鳴らさない（ブラウザの決まり）。音は消せる。ファイルが重いなら先に読み込まず、タイトルのあとで裏で読む

### 4. ひとりで遊ぶ・同じ端末で遊ぶの設定（ロジックは対応済み）
`js/main.js` の `startLocal` は今、`new Game()` に `setup` を渡さず、2人・城の種類なし・デッキ共通でしか遊べない。ロジックは次をすでに持っている（CLAUDE.md「STEP 5」「チーム戦」）。
- 「ひとりで遊ぶ」で選べるようにする：**CPUの強さ（今のまま）／人数（2〜8。CPUが残りの席）／勝ち方（最初に落とした人・最後の1人）／城の種類／デッキ（`deckMode: "own"`）／チーム戦（自動で2チーム）**。選ぶのは任意で、**何も選ばずに押せば今までどおり2人ですぐ始まる**（最初の1分を長くしない）。「おすすめ」ボタンを1つ置く
- 3人以上は広場の盤面（PR #53）を使う。CPUの手番が長くならないよう、CPUの待ち時間を人数で短くする
- 完成の目安：8人（自分＋CPU7）で、広場の盤面で、決着まで止まらず遊べる

### 4b. CPUの強さの割り当てを直す
`js/main.js` の `CPU_LEVELS` は、`easy=rush`・`normal=defensive`・`hard=smart`。最新の測定（`node tests/sim/run.js --games 200 --match <戦い方>,random`、先攻のとき random に勝つ割合）は **rush 50%・defensive 23%・smart 97%** で、**「ふつう」が「よわい」より弱い**（逆転している）。`js/game/strategies.js` の戦い方は触らず、割り当てだけを測り直して、弱い順に並ぶようにする。測った表をPRに書く。足りなければ「ロジック側で必要な変更」として書く。

### 5. 結果画面と「もう1回」
- 結果画面に試合のまとめを出す：手番数、与えた城ダメージ、倒した魔物の数、使ったカードの枚数（`gameOver` までのイベントを画面側で数える）。勝ちは派手に褒め、**負けた人も「もう1回」と思える**ように、ボタンは1タップで同じ設定の再戦
- 戦績（勝ち・負け・連勝）を `localStorage` に覚えて、タイトルに小さく出す。消すボタンも置く

### 6. 読み込みを軽く・オフラインでも動かす
今は画像だけで約10MB（230ファイル）を最初に全部読む。
- タイトルに必要な画像だけ先に読み、残りは裏で読む（読み込み画面 `#loading`、`preloadAssets` は私が入れた。進み具合の出し方は活かす）。まだ読めていない絵は、仮の絵ではなく読めるまで待つか、小さな見た目で代用する
- 画像の圧縮（可能なら WebP。ただし再配布・ライセンスは守る）。目標：タイトルが出るまでの転送量を1MB以下に
- PWA：`manifest.webmanifest` とサービスワーカーで、ホーム画面に追加でき、2回目からオフラインでも「ひとりで遊ぶ」が動く（`file://` ではなく http(s) 前提。オンライン対戦の `/api/*` はキャッシュしない）。更新があったら、次の起動で新しい版に変わる

### 7. 絵と見た目の足りない分
`assets/STYLE.md` の指示文・`style-reference.png` で作る。
- 城の種類（とりで・魔法の塔・兵舎）それぞれの城の絵（青・オレンジ・壊れ具合4段階。今は全部ふつうの城の絵）。城の種類が盤面で見分けられる
- 精霊（火・水・風・土、小・大）の盤面での見た目、ターン開始時の演出
- カードの裏面、タイトル背景の小さな動き、勝利／敗北の画面の絵
- 3人以上のとき、席ごとの色（今は青・オレンジの2色だけ。最大8色。色だけに頼らず、名札・印でも見分けられる）

### 8. 見た目の崩れをなくす・アクセシビリティ
- 幅 320／360／390／430／768／1280px、縦横それぞれ、iPhone のノッチ（`env(safe-area-inset-*)`）で、タイトル・盤面・手札・カード説明・結果・部屋・図鑑・設定が崩れない。はみ出し・重なり・切れた文字をなくす。確かめたスクリーンショットをPRに貼る
- キーボードだけでも遊べる（Tab で移動・Enter で決定・Esc で閉じる）。ボタンに `aria-label`、状態は色だけでなく文字・印でも示す
- 実機のタッチ（ピンチでの拡大縮小など）は自動では確かめられない。**確かめられなかったことは、PRに「未検証」と正直に書く**

### 9. 画面の自動チェック
- Playwright で、「タイトル → ひとりで遊ぶ → 1手出す → ターン終了 → 結果まで」のスモークテストを書き、コンソールにエラーが出ないことと、主要な画面が表示されることを確かめる。置き場所は `ui-tests/`（新しいフォルダ。`tests/` はロジック担当なので触らない）。**CLAUDE.md の担当表に追加が必要なので、PRに「相手側で必要な変更」として書く**。実行は `node ui-tests/smoke.js`（外部パッケージは Playwright のみ。リポジトリには入れず、あるものを使う）

### 10. 説明の更新
- 「遊び方」・カード図鑑・`assets/README.md` を今の仕様に合わせる（`assets/README.md` は「カード71種・兵士6種」のままで古い。今はカード85種・兵士20体）：兵士の4系統と射程・帰還、道5マス、広場、チーム戦、魔物の放置の怖さとごほうび
- 遊び方は短く、図つきで。長い文章から始めない

## PRの出し方

- 1PR＝1項目（上の1〜10）。説明文に「何を変えたか／確かめたこと（スクリーンショット）／**未検証のこと**／相手側（ロジック担当）で必要な変更」を書く
- **自分のPRを自分でマージしない。** 相手の承認を待つ。自動マージは設定しない
- 迷ったこと・仕様にないことは、実装する前に人間に聞く
