# Codex への依頼：MP・魔物の成長まわりのデザインと、足りない画面を作る（UI担当）

あなたはブラウザカードゲーム「キャッスルフィールド」の **画面（UI）とデザイン担当** です。
ロジック側で、次の仕様が入りました（ブランチ `claude/dazzling-rubin-jo7oec`、`CLAUDE.md` の「MP・武器の加算・魔物の成長・降参の観戦」の節）。
**見た目が仮のままの部分と、画面にまだ足りない部分を、自分で見つけて作ってください。** 下は最低限の一覧で、これ以外に「遊んでいて足りない・分かりにくい」と感じたものも、自分で考えて足してください（足したものは PR の説明に書く）。

## 最初にやること

1. `CLAUDE.md` を**最後まで読む**（仕様の正。特に「チーム開発のルール」「ゲームづくりの原則（桜井流）」「画像素材」「ロジックとUIの約束」）。`assets/STYLE.md` の絵柄の決まりを読む。
2. 土台：`claude/dazzling-rubin-jo7oec` が main に入っていなければ、そこから `feature/<内容>` を切る。入っていれば `git pull origin main` から。main に直接コミットしない。**1つのPRは1つの機能**（大きければ分ける）。
3. 起動：`python3 -m http.server` → `http://localhost:8000`。ひとりで遊ぶ：`?local=1&cpu=hard`、デバッグ：`?debug=1`（`window.castlefield.game()` で手札を作れる）。
4. 触っていいのは UI 担当の範囲（`index.html`・`css/`・`js/ui/`・`js/main.js`・`assets/`・`sw.js`・`ui-tests/`）。ロジック（`js/game/`・`data/`・`tests/`・`server/`）は**変更しない**。必要なら PR の説明に「ロジック側で必要な変更」として書く。
5. 必ず通す：`node --test`、`node ui-tests/smoke.js`。配るファイルを変えたら `node js/ui/build-precache.js` を実行して `js/ui/precache.js` も同じPRに入れる。画面は Playwright の Chromium（390×844 と 360×640）で、自分の目でスクリーンショットを見て確かめる。

## 新しく入った仕様（画面の対象）

- **MP**：攻撃の魔法と精霊は、レアリティのぶん MP を使う（コモン1〜レジェンド5）。上限20、開始10、自然回復なし。マナ回復カード5種（`manaShard` → `manaDrop` → `manaCrystal` → `manaSpring` → `worldTreeDew`、+1/+2/+5/+10/+20）。`getState()` に `maxMp`・`mpCosts`・`players.pX.mp`、イベント `mpChanged`。
- **魔物の成長**：放置すると3周ごとにレアリティが上がり強くなる（イベント `monsterEvolved`、`getState().monsters[].evolveCount`）。後半ほど高レアの魔物が出やすい。
- **幸運の加護**（`upgrades.json` の `permLuck`）：その試合ずっと、引くたびに一定確率でレア以上が出やすい。`players.pX.permLuck`。
- **武器は重ねられる**（攻撃は足し算・属性は上書き）。**開幕コイン0**。騎兵の速さ3。
- **降参（3人以上）**：城が壊れて抜け、残りを観戦（`castleDamaged` の `source.kind === "surrender"`、`playerEliminated`）。

## 作るもの（最低限）

### A. 絵（`assets/STYLE.md` の共通の指示文を使う。背景透明PNG。出どころを `assets/CREDITS.md` に書く）
1. **マナ回復カード5枚の絵**（`assets/cards/card-mana-shard.png` など。512×512）：小さな青い光 → 水晶 → 泉 → 光の柱 → 世界樹のしずく、と段階で豪華に。`js/ui/art.js` の `CARD_ART` に割り当てる（今は「魔」の仮の絵）。
2. **魔物の絵 12種**（`MONSTER_ART`。今は名前の1文字目の仮の絵）。強い魔物ほど大きく迫力を出す。
3. **MP のアイコン**（`assets/ui/icon-mp.png`）：上のバーの「✦」と手札の「✦3」の札を、この絵に置きかえる。
4. **魔物が育った印**：レアリティが上がるたびに魔物のまわりに足されるオーラ・王冠・炎などの絵（`evolveCount` に応じて段階で変える）。
5. **「幸運の加護」の強化アイコン**（`upgradeIcon`）と、**城が降参で崩れた絵**（`castles/castle-*-ruined.png` など）。

### B. 演出・画面（桜井流：手応えを出す。ただし長すぎず、タップで飛ばせる）
1. **MP バー**：数字だけでなく、青いゲージ（20個の宝石でも可）にする。減る・増えるときに光る。足りないカードに触ったとき、「あと○足りない」をゲージの横に赤く出す（今は理由の文だけ）。マナ回復カードを出したときは、ゲージが満ちる演出（レアリティが高いほど派手に）。
2. **魔物が育つ演出**（`monsterEvolved`）：ごほうびカードの枠が1つ上の色に変わる・オーラが強まる・数字（HP・攻撃）が膨らむ。放置の怖さが一目で伝わるように。魔物の札に「育った回数」と「次に育つまであと何周」を出す。
3. **合成の演出**：今は光・火花・揺れまで。**レアリティごとに別の演出**（コモンは控えめ、レジェンドは画面全体が光って音が大きい）、**適応（虹色）専用の演出**、**合成できるペアを手札で見分ける印**を強くする。音（`Sound.js`）もレアリティで変える。
4. **魔物を倒したごほうび**（`monsterDefeated` の `lucky`・`rewardRarity`）：カードがガチャのように飛び出す演出。ラッキー（1つ上）のときは特別に派手に。
5. **降参・観戦モード**：降参した人の城が崩れる演出、観戦中の帯（今は文字だけ）、観戦中でも試合の流れが見やすい速度表示、メニューから「タイトルへ戻る」がすぐ押せること。誰が抜けたかを席の一覧に出す。
6. **勝ったときの演出**（まだ弱ければ）：勝者を派手に褒める。降参で勝ったときの文も。
7. **武器が重なる表示**：兵士の上に「武器×2」「攻撃+3」のように、重ねたぶんが分かる印。属性が上書きされたときの変化（色が変わる）。

### C. 足りない部分は自分で見つけて作る（必須）
自分で一通り遊び（ひとりで・3人以上の広場・チーム戦・オンライン）、次を点検して、**足りないもの・分かりにくいものを作る**：
- 初めての人が**説明なしで**分かるか（チュートリアル `Tutorial.js` に MP・合成・魔物の成長を足す。最初の1分で面白さが伝わるか）
- 「排出率を見る」画面（`getDropRates()`）に、マナ回復カード・魔物の成長（何周でどのレアリティになるか）が出ているか
- 図鑑（`CardGuide.js`）に MP のコスト・マナ回復の系統・合成の道すじが出ているか
- 強化の画面（`UpgradePanel.js`）で、幸運の加護の効果（今の確率）が分かるか
- 手札が多いとき・小さい画面（360×640）・横向きで崩れないか。文字が小さすぎ・タップしづらい所がないか
- 待ち時間が長い演出、音が大きすぎ・うるさい所はないか。演出は全部タップで飛ばせるか（`accessibility.css` の動きを減らす設定も尊重する）
- 色だけに頼った表示がないか（色覚への配慮）、スクリーンリーダー向けの文があるか
- ほかに「あったら遊びやすくなる」と思うもの（例：MP を回復できるカードが手札にあるときの目印、魔物が次に育つまでの予告、試合の履歴の確認）

## 守ること

- 絵柄は `assets/STYLE.md` でそろえる。作者・絵柄がばらばらの素材を混ぜない。ライセンスを守り、`assets/CREDITS.md` に記録する。1枚300KB以下。
- カードの数値・ルールは変えない（`data/` はロジック担当）。画像の割り当ては `js/ui/` に書く。
- 押して何も起きない操作を作らない。出せない理由は必ず表示する。
- PR の説明に、**何を作ったか・スクリーンショット・確かめたこと（`node --test`・スモークテスト・実機の画面）・自分で足したもの・相手側で必要なロジック変更**を書く。自分のPRを自分でマージしない。
