# CPU の任意アクション追加（feature/skill-cpu-more）

base＝feature/online-skills。`js/game/strategies.js` の `CPU_SKILL_ACTIONS` に、今まで使わなかった7つを足し、対象を選ぶアクションに単純な点数を付けた。乱数は使わない（決定論的）。**勝率は測っていない（未検証）**。

## 仕組みの変更
- `pick(options, env)`：`env`（`skillEnv`）は盤面の見取り図（自分・相手の兵士の soldierId → 状態、`laneEnemies(roadId)`、`laneScore(roadId)`、レーン長 `L`）。`bestBy(score, min)` が点数最大（同点は一覧の先頭）を選び、`min` 未満なら null＝**そのターンは見送る**
- `takeSkillActions(game, pid, phase, ctx?)`：ctx を渡すとそのカード表・ルールで評価（takeTurn の中では設定済み。単体のテスト用）
- スキルがなければ今までどおり何もしない・乱数も使わない（tests/sim の normal / classic（スキルなし）/ factions の出力は base と一致）

## 追加した7アクション（損をしにくい条件）
| ID | phase | 使う条件 |
|---|---|---|
| H08 運命操作 | pre | 今の MP で出せない手札を、山札の上3枚の「出せるカード」と交換（出せる兵士3＞出せる魔法2。差2以上のときだけ。出せる手札は手放さない） |
| H07 再編成 | pre | 手札2枚以上で、今の MP より3以上重い魔法（兵士以外）があるとき、いちばん重い札を捨てて1枚引く |
| V05 送還 | post | MP に空きがあり、体力が最大の3分の1以下のトークンだけ（元気なトークンは残す） |
| X29 生贄の儀式 | post | 城HPかMPが2以上回復できるとき、体力が3分の1以下で、敵城に届く手前（position < L-1）の兵士だけ |
| K05 交代 | post | 敵のいるレーンで、前後とも近接の兵士。後ろの攻撃力が前以上かつ体力＋シールドが前以上、点数差2以上のとき強い方を前に |
| U06 戦術転換 | post | 敵のいないレーンの近接兵士（体力半分以上）を、敵のいるレーンへ（レーン点数の差2以上。敵1体＝2・魔物＝1） |
| X44 先読み | post | 次のドローの先頭2枚のうち、2枚目のほうが出しやすい（次ターンの最大MPで）ときだけ入れ替え。それ以外は予約しない |

順序：pre は H08→H07 を最後（ドローを増やすものの後）、post は V05・X29 を先頭（得た MP を V07・X43 に回せる）、K05・U06 を K04・K08 の前（配置を整えてから移動・進軍）。

## 対象選択の点数（既存アクション）
H03・G04・G06：強いカード（兵士＝10＋体力＋攻撃×2、魔法＝MPコスト）／I08：攻撃×2＋最大体力の大きい敵の写し／X43：敵のいるレーン・+3で倒せる・前にいる兵士／D07：敵のいるレーンの前の兵士／T04：体力のいちばん少ない兵士／S08：倒せる敵＞前の敵／T08：倒せる敵＞前の敵／B07：倒せる敵は最少量で、倒せなければ最大量で前の敵／K04：敵のいるレーンへ（点数差が最大。見送りはしない＝従来どおり使う）／K08：敵のいないレーンで城に届く・前の兵士、敵レーンでは倒せる相手がいるときだけ。

## テスト

- `docs/skilltree-200-coverage.md` は `node tools/skilltree-coverage.mjs` で再生成（CPU列の7つが skip → use）

## 未対応・注意
- 勝率・強さは未測定（大規模シムはしていない）。条件は保守的に決めた見積もりで、調整の余地がある
- 点数は盤面の単純な見積もり。武器・属性・天候・反応・魔物の有無まで読まない。K05 は「この兵士がすでに今ターン攻撃したか」を見ない
- X44 は swap だけ予約（そのままにする選択は何もしない）。H07 は進軍前（pre）に判断するので、その後に MP が増えて出せるようになる札を捨てることがある
- U06・K04 は兵士の移動で「すでにぶつかっている敵」から離れる判断は U06 では禁止（敵のいるレーンの兵士は動かさない）。K04 は従来どおり
- G06・G04 は一覧に種類しかないので、強さはカード定義の体力・攻撃から見積もる（蘇生後の体力は読まない）
