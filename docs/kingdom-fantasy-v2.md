# 王国ファンタジー改修 第2レビュー対応

> 後続の仕上げ・WebP配信・自然決着の検証は [第3版](kingdom-fantasy-v3.md) を参照。以下は第2版時点の記録。

PR #202の続き。既存カードの絵柄と `assets/STYLE.md` を基準に、配色だけの段階から、専用画像・系統別構成・画面構成まで実装した。調査時の監査は `kingdom-fantasy-audit.md`、この文書は追加実装の最終状態を記録する。

## スキルツリー

- 19系統をそれぞれ紋章・専用色・見出しのある区画へ配置。通常8ノードの枝を横向きの二段構成にし、奥義を区画の右側に大きく配置した。
- 系統配置は横断関係の交差・距離を目的関数にして調整。横断48ノードを区画間の通路へ置き、接続線は区画の外周・通路に沿って配線する。STARTからの共通線は背景に抑え、取得済みや選択経路を強調する。
- 配置は `js/ui/skillTreeLayout.js` のUI座標だけ。元の286辺、200スキルの効果・コスト・必須・横断の接続先を変更しない。
- 通常=木と金の円形、奥義=王冠・宝石・月桂樹の大菱形、横断=道の彫りを持つ六角形、START=青い王国盾。画像生成した枠を使用。
- 全200効果に専用画像を割り当て、19奥義は大きい効果イラストと専用枠。未取得でも画像は暗くしない。状態は外周・記号・破線/点線で判別する。
- PCの初期表示は全区画。縮小時に全スキル名を同時に読む方式ではなく、絵・種類・系統を識別し、系統フィルタでその8ノードを拡大する。
- スマホはSTARTと周辺の取得可能ノードを見渡す倍率。密集時の拡大・取得可能一覧を維持。拡大に依存しない48px当たり領域は最寄り中心で判定する。
- 詳細はPCでは地図と別の右列、スマホ縦向きでは地図の下に別領域を設ける。詳細がある間は検索欄・検索結果を畳み、地図と取得ボタンの高さを確保。横向きも二列で分離する。
- マウスはpointerup内で即時選択。タッチだけダブルタップ判定を待つ。PCに320ms待機はない。

## 実際に制作・組み込んだ素材

`assets/ui/kingdom-v2/` の14PNG。単にプロンプトを作成した段階ではなく、ゲームがアトラス内の画像を実際に表示する。

| 対象 | 制作と組み込み |
|---|---|
| 19系統 | groups.pngの意味に合う専用アイコン。模倣は鏡、時間は砂時計、墓地は墓石と魂、攻城は破城槌等 |
| 200スキル | 25セル×8枚。各IDの名前・効果全文を生成時に指定。IDごとの割り当てを固定し、全200セルを使用 |
| 枠・奥義・横断 | decor.png。4種類のノード枠を使用。横断の橋はフィルタにも使用 |
| ホームナビ | account/deck/battle/gacha/settings等の専用絵。操作方向・閉じる等の記号は既存のベクターを保持 |
| CPU難易度 | 見習い兵、騎士、王国騎士を実際の選択カードに組み込み。説明・見出し・矢印を分離したレイアウト |
| 不足カード | 新陣営25種類を生成画像で対応。他4種類は意味が一致する既存の勇者・神剣・神盾・天罰を使用。クラシック固有の聖火球・闇火球・城壁斉射も生成 |

カード230定義すべてに対応し、対応漏れゼロ。クラシック32件も明示的に画像を割り当てた。通常兵士の青・オレンジ駒は既存画像を保持。アトラス絵をカードの3D拡大テクスチャへ描画する処理も追加。

画像・寸法・ハッシュ・セル用途は素材ディレクトリのREADMEとimage-inventory.json、全カード対応はcard-coverage.jsonを参照。生成画像の未使用候補セルも明記している。人手で生成画像を切り貼りして別の絵として数えていない。

## 共通デザインシステム

`css/home-reborn.css` から色・背景・枠・影等の装飾と対戦準備の旧指定を除去し、ホームのレイアウトに限定。`css/kingdom-system.css` を共通の色・紙・木・金・ボタン・タブ・パネル・ダイアログの管理元にした。スキルツリーCSSも上書きを積み重ねず再構成した。

CPU難易度は画像付きの選択カードへ変更。主役画像、難易度名、実際の既存CPU説明、進む矢印を別の領域に配置し、任意設定を主操作の後へ移動。PC/スマホで余白とサイズを分ける。難易度の戦略や強さは変更しない。

ホーム5タブ、CPU選択、対戦準備、デッキ編集、図鑑、ガチャ、アカウント、設定、ヘルプ、モード/その他ダイアログ、戦闘HUD/手札、結果画面を確認。既存の可愛いカード絵や3D城モデルを別の作品へ描き替えない。

3D描画は通常時30Hz、動きを減らす場合は最大10Hzに描画頻度を抑制。描画更新のタイミングだけで、ゲームの進行・CPU・ダメージ・スキル効果には関与しない。

## 検証と資料

- 既存のツリー・表示モデル・ホーム空・3Dカメラ・カード枠のテスト37件成功。
- 追加画像対応テスト5件成功。200効果、19系統、4枠、ナビ、カード230件＋魔物カード12件、表示座標201件を検証。
- 1440×900、820×1180、390×844、320×568、844×390で実際のSVGノードをクリック/タップし、取得・保存・検索・ピンチ・ダブルタップ・パン・全体・現在地・キーボードを確認。PCはpointerup直後に選択されたことを確認。
- 全画面資料は `assets/review/kingdom-fantasy-v2/README.md`。PC/スマホの各画面30枚、ツリーの5サイズ、全スキルと全カードの画像対応一覧を含む。
- 通常3D対戦はPC 1440×900とスマホ390×844の両方で成功（各4手番、1枚使用、ページエラー/同期警告なし、結果/再戦）。`kingdom-battle-3d.js`。実WebGLコンテキストの有効性を確認し、実際のUIで兵士配置、手番、CPU行動、降参の二段階確認、結果・再戦を通す。終了は降参であり、自然決着までの長時間試合とは分けて記録する。
- 再現性のため、PC/スマホの基本3DスモークではOSの「動きを減らす」を指定し、演出時間だけ短縮する。3Dモデル・WebGL・画質は維持し、軽量/2Dモードは使わない。追加で通常の動きのある3D（スマホ、no-preference）でも同じ4手番・結果/再戦が成功。演出時間だけは検証用に短縮する。
- 最初の通常3D長時間スモークとPCの短い待機設定は、ソフトウェア描画下でタイムアウト。テストは3Dを2Dへ落とさず、PCの待機上限を60秒としている。

## 未対応・制限

- 実機iOS Safari/Androidでの指の感覚・読み上げ・長時間GPU負荷の評価は未実施。仮想画面サイズとChromiumの実タッチイベントによる確認。
- 全200効果の絵は効果説明から生成して割り当てたが、生成絵の最終アートディレクター承認は未実施。ゲーム中の正確な効果は常に既存の詳細説明を表示する。
- 3D試合の自然決着までの長時間スモークは未通過。今回の3D完了経路は実際の降参操作による結果と再戦。表示品質/フレームレートの実機保証はしない。
- 画像PNG14枚は生成原画のまま保存。通信量をさらに減らすWebP/AVIF配信・低解像度アトラスの併用は今後の改善候補。
- 全体表示では200個の名前を同時に読ませず、系統拡大と検索で詳細へ進む。全体表示での密集を完全にはなくせない。

`js/game/`, `data/`, `server/`, `tests/`, `js/main.js` は変更していない。同じ専用ブランチ・PR #202を更新し、mainにはpush/mergeしない。
