# Codex への依頼：オンライン対戦ゲーム化の新画面を、本格的なデザインに仕上げる（UI・画像担当）

あなたはブラウザカードゲーム「キャッスルフィールド」の **画面（UI）とデザイン・画像素材の担当** です。
ブランチ `claude/castlefield-phase6-ops`（PR #111 → #123 → #126 → #127 → #129 → #132 の積み上げ。まだ main に入っていない）で、アカウント・ホーム・ランク・フレンド・ショップ・ガチャ・スキン・ミッションが**ロジックと機能する最低限の画面**で入りました。**画面は動くが、デザインは仮です（既存の木・羊皮紙の部品を寄せ集めただけ。ランクのエンブレムは SVG の仮、スキンは色を変えただけ）。** これを、スマホゲームとして完成度の高い見た目にしてください。画像も作ってください。

## 最初にやること

1. `CLAUDE.md` を**最後まで読む**（仕様の正。「チーム開発のルール」「ゲームづくりの原則（桜井流）」「画像素材」「ロジックとUIの約束」）。`assets/STYLE.md`（絵柄の決まり・共通の指示文）と `docs/accounts.md`（新機能の仕様・API・画面の説明。末尾の各 Phase の「画面」の節）、`docs/ui-design.md` を読む。
2. 土台：上のブランチ（または、その後 main に入っていれば `git pull origin main`）から `feature/<内容>` を切る。**main に直接コミットしない。1つのPRは1つの画面群**（下の「進め方」の順に分ける）。PR は相手の承認を受けてからマージする。
3. 起動：オンラインとアカウントの機能は `node server/server.js`（既定 `http://localhost:8787`。データベースは `CF_DB_PATH` で一時のファイルにするとよい）で動く。`python3 -m http.server` ではアカウント機能が出ず、従来のタイトルになる。ゲストでも、ホーム・ショップ・ガチャ・スキン・ミッションは触れる。**会員（ランク・フレンド）は Google/Apple 連携が要るが、確認用はデータベースの `users.kind` を `'member'` に更新すればよい**（`ui-tests/ranked.js`・`ui-tests/social.js` に手順がある）。コインは `wallets` に直接入れて試す（`ui-tests/collection.js` が見本）。
4. 触っていいのは **UI担当の範囲だけ**：`index.html`・`css/`・`js/ui/`・`js/main.js`・`assets/`・`sw.js`・`manifest.webmanifest`・`ui-tests/`。**`js/game/`・`data/`・`tests/`・`server/`・`CLAUDE.md` は変更しない**。必要な変更は PR の説明に「ロジック側で必要な変更」として書く。
5. **変更しないもの（別のエージェントが作業中）**：`js/ui/CardZoom.js`・`js/ui/Hologram.js`・`css/card-zoom.css`・`css/hologram.css` と、カードの立体化・偏光・拡大の描画。競合しそうなら別ファイル・別コンポーネントで作る。
6. 必ず通す：`node --test`（ロジック。349件）、`node ui-tests/smoke.js`、`node ui-tests/account.js`、`ranked.js`、`social.js`、`collection.js`、`missions.js`（すべて Playwright の Chromium。**テストが見る要素の id・クラス・`data-*` を変えるときは、テストも直す**）。配るファイルを変えたら `node js/ui/build-precache.js` を実行して `js/ui/precache.js` も同じPRに入れる。
7. 画面は実際に表示してスクリーンショットを見て直す（**確かめずに完成と言わない**）。サイズ：`390x797`（ホーム画面アプリ）・`375x667`・`360x640`・`320x568`・横向き `844x390`・PC `1280x800`。上が切れない・横にはみ出さない・押せるものは44px以上。セーフエリア対応。

## 方針（守ること）

- 見た目は **明るいカートゥーン調のファンタジー**（`assets/STYLE.md`）。太めのこげ茶の輪郭線・やわらかい影・2頭身。木・羊皮紙・石・金属の飾りで統一する。**画像生成AIで作る絵は、必ず STYLE.md の共通の指示文を先頭に付け、絵柄の見本（`assets/style-reference.png`）を添付する。** 作者や絵柄がばらばらの素材を混ぜない。
- **押して何も起きない操作を作らない**。出せない・買えない・まだ使えないものは、理由を表示する（準備中のものは「準備中」と明示）。押した反応（沈む・光る・音）を必ず付ける。
- 演出は短く、**タップで飛ばせる**。ガチャ・レベルアップ・昇格・勝利は派手に褒める。設定「動きを減らす」（`reduced-motion`）のときは動かさない。
- 数値・確率・価格・景品は `data/` にあり、**画面では表示するだけ**（コードに書き込まない）。ランクや残高・勝敗をクライアントから変える操作を作らない。
- 画像の割り当ては **画面側（`js/ui/`）で決める**。`data/` に画像の情報を足さない（足したいときは PR の説明に提案として書く）。
- 素材の形式：背景が透明な PNG、1枚 300KB 以下、ファイル名は小文字の英字とハイフンだけ。**素材を足すときは、同じPRで `assets/CREDITS.md` に「ファイル名・作った道具・ライセンス・作った日」を書く。**
- 日本語の文字は絵に入れない（画面側で重ねる）。文字が読みやすい大きさ・コントラストを保つ。

## やってほしいこと（優先順。1つずつ PR にする）

### A. ホーム画面（`js/ui/Home.js`・`css/home.css`）
いまは「木の帯＋羊皮紙のカード＋3列のタイル」。**ゲームのホームらしい構成に作り直す。**
- 上：プレイヤーのアイコン・名前・称号・レベルと経験値バー・コイン・お知らせ・設定。
- 中央：背景に**城のイラスト**（ホーム用の背景を新しく作る。`assets/bg/`）。選んだモード・デッキ・ランク（エンブレム）・シーズン・**大きな対戦開始ボタン**を目立たせる。
- メニュー（12項目）は、**専用のアイコン絵**（いまはコードの線画）にして、グループ分け（対戦／コレクション／ソーシャル／その他）で優先順位を明確にする。未受け取りのバッジ（ミッション・フレンド・レベル報酬）の見た目を整える。
- 世界（王国／戦国・準備中）の切り替えの見た目。ロード中・通信失敗・空の状態も作る。
- 初回（ゲスト）に「アカウントを連携するとデータを引き継げる」案内を、邪魔にならず分かりやすく出す。

### B. ランク（`js/ui/RankEmblem.js`・`js/ui/RankedView.js`・`css/home.css`）
- **9階級（Iron・Bronze・Silver・Gold・Platinum・Diamond・Ascendant・Immortal・Radiant）のエンブレムを、オリジナルのイラストにする**（他作品の素材・ロゴ・ランク図柄を流用・模倣しない）。階級が上がるほど豪華に。ディビジョン（I〜III）の見せ方、認定戦中（「？」）の表示も。`assets/ranks/rank-<階級>.png` などで作り、`RankEmblem.js` で差しかえる（いまの SVG は、読み込めないときの代わりに残してよい）。
- ランク画面：相手探しの待機（探している演出・経過時間・やめる）、成立の演出、昇格・降格・認定戦完了の演出（結果画面の RP 表示）、ランキング一覧、シーズンの記録。

### C. ショップ・ガチャ・スキン（`js/ui/CollectionView.js`・`js/ui/Cosmetics.js`・`css/home.css`）
- **スキンの専用の絵を作る**（いまは色を変えただけ）。`data/shop.json` の景品（兵士スキン6・城6・カード裏面4・攻撃エフェクト4・勝利演出3・アイコン6・称号5）が対象。優先は **兵士スキンと城の外観**（盤面に出る）。`assets/skins/…` に置き、`js/ui/` に「景品ID → 画像」の対応表（例：`js/ui/skinArt.js`）を作って `Cosmetics.js`・`Renderer.js` の描画に使う。画像がない景品は、今の色替えのまま動くこと（**スキンを持っていなくても標準の見た目で遊べる**）。
- カード裏面は、ゲーム中に見える場所を作ってよい（相手の手札の枚数表示・山札など。`js/ui/`・`css/` の範囲で）。
- ガチャ：**演出を本格的に**（ガチャを回す→開く→レアリティごとに違う演出。エピック・レジェンドは特別に。10連は順に見せ、タップで飛ばせる。重複が交換ポイントになる見せ方）。排出率・救済（天井）・履歴・交換の画面を見やすく。
- ショップ：景品の見本の見せ方（装備した姿のプレビュー）、種類ごとの並べ方、買えない理由の表示。

### D. フレンド・プロフィール・ミッション・結果画面
- フレンド画面（`SocialView.js`）：一覧のオンライン状態・パーティー・招待のバナーの見た目。
- プロフィール（`ProfileView.js`）：アイコン・称号・戦績の見せ方、他人のプロフィール。
- ミッション（`MissionView.js`）：進み具合・受け取りの演出（コインが増える）。
- 結果画面（`Progression.js` ほか）：経験値・コイン・ランクの変化・レベルアップの演出を、1つの見やすい流れにする（長くしない。タップで飛ばせる）。
- プレイヤーのアイコンの絵（`assets/units/*-blue.png` の流用をやめて、プロフィール用に新しく作ってよい）。

## 進め方

1. まず **A（ホーム）** をデザインして、スクリーンショットを見せられる状態にする。方針に迷ったら、実装する前に PR の説明か人間に聞く（絵柄・色・構成の大きな変更は特に）。
2. A → B → C → D の順に、機能ごとの PR にする。各 PR の説明に、**変更した画面のスクリーンショット（前後）・通したテスト・未完了のこと**を書く。
3. 画像を作ったら、プロンプト（画像生成AIに入れた文）を `assets/STYLE.md` か PR の説明に残す（あとで同じ絵柄で足せるように）。

## やってはいけないこと

- ロジック・サーバー・`data/`・`CLAUDE.md` の変更。ランク・コイン・景品・勝敗を画面から決める仕組み。
- カードの立体化・偏光・拡大（`CardZoom.js`・`Hologram.js` ほか）への変更。
- 他作品の素材・図柄の流用。出どころ不明の画像。
- テストを無効にして通すこと、確かめていないものを「できた」と書くこと。
