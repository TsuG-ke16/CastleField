# Codex への依頼：全体のデザイン・UI の見直しと、デッキ編成画面づくり（UI担当）

あなたはブラウザカードゲーム「キャッスルフィールド」の **画面（UI）とデザイン担当** です。
ブランチ `claude/youthful-bohr-5u7ygu`（PR は main へ）で、次の機能がロジックと最低限の画面で入りました。**見た目はまだ仮・寄せ集めです。ゲーム全体のデザインと UI を見直して一貫したものにし、必要な画像とアニメーションも作ってください。** 特に **デッキ編成画面** は作り直しです（下の「A」）。

## 最初にやること

1. `CLAUDE.md` を**最後まで読む**（仕様の正。特に「チーム開発のルール」「ゲームづくりの原則（桜井流）」「画像素材」「ロジックとUIの約束」と、末尾近くの「天候・魔物の駒・チャット・体力ゲージ」「デッキ編成（コスト制）」）。`assets/STYLE.md`（絵柄の決まり・共通の指示文）を読む。
2. 土台：上のブランチが main に入っていなければそこから、入っていれば `git pull origin main` から、`feature/<内容>` を切る。main に直接コミットしない。**1つのPRは1つの機能**（大きいので分ける。順番は下の「進め方」）。
3. 起動：`python3 -m http.server` → `http://localhost:8000`。ひとりで遊ぶ：`?local=1&cpu=hard`、デバッグ：`?debug=1`（`window.castlefield.game()`）。天候を試す：`?local=1&cpu=hard&debug=1&rules={"weatherFirstRound":1,"weatherChangeChance":1}`（URL エンコードして渡す）。オンライン：`node server/server.js`（8787）。
4. 触っていいのは UI 担当の範囲（`index.html`・`css/`・`js/ui/`・`js/main.js`・`assets/`・`sw.js`・`manifest.webmanifest`・`ui-tests/`）。ロジック（`js/game/`・`data/`・`tests/`・`server/`）と `CLAUDE.md` は**変更しない**。必要なら PR の説明に「ロジック側で必要な変更」として書く。
5. 必ず通す：`node --test`、`node ui-tests/smoke.js`（今は「山札の同期警告」で落ちる既知の問題がある。**今回の変更で警告を増やさない**。直せるなら直してよい）。配るファイルを変えたら `node js/ui/build-precache.js` を実行して `js/ui/precache.js` も同じPRに入れる。画面は Playwright の Chromium（390×844 と 360×640）で、自分の目でスクリーンショットを見て確かめる。

## A. デッキ編成画面を作り直す【最優先】

**ポケモンカードのスマホゲームのように、見て分かる・触って分かる画面にする。** 今は文字の一覧に ＋/− が付いているだけ。次を満たす。

1. **カードの絵で編成する**：一覧は文字ではなく、実際のカード（枠・絵・コスト・名前・効果の短い表示。`cardView.js` の `mountMiniCard` や手札のカードの見た目を再利用してよい）をグリッドで並べる。所持カードの全種類を、レアリティ・種類（兵士／攻撃魔法／回復／防御／武器／精霊／コイン・MP など）で絞り込める。並べ替え（コスト順・レアリティ順・名前順）。
2. **デッキはカードの並びで見える**：画面の上か下に、今のデッキを「カードが並ぶ帯」で常に表示（同じカードは重ねて「×3」）。タップで1枚減らす、長押し（またはカード詳細）で説明。**デッキの中身が一目で分かる**ことが最重要。
3. **コストを視覚化**：合計コストのゲージ（90〜100 の範囲が目盛りで分かる。足りない＝黄、範囲内＝緑、超過＝赤）、レアリティごとの枚数と上限（例：レア 12/20）を色つきの小さなメーターで。**カードを足せないとき（同じカードの上限・レアリティの上限・コスト超過）は、押せない見た目にして、触れたら「なぜ足せないか」をその場に出す**（押して何も起きない操作を作らない）。理由の文はロジックの `checkCostDeck` の `problems` を使う。
4. **コストの低い・高いが見える**：カードの角にコストの宝石（レアリティの色）を大きく出す。
5. **偏光（ホログラム）必須**：ポケカのキラカードのように、**レア以上のカードに光沢（偏光）の演出**をつける。
   - 端末の傾き（`DeviceOrientationEvent`。許可が必要な端末ではボタンで許可を求める）か、指でなぞった位置（`pointermove`）に合わせて、カードの上を虹色・金色の反射が動く。傾き・ポインタが使えないときは、ゆっくり自動で流れる。
   - レアリティで見た目を変える：レア＝青白い細い光、エピック＝紫〜虹のグラデーションと粒子、レジェンド＝金のホイル＋虹＋きらめき、スペシャル（適応・天候の呪文）＝全面が虹色のホログラム。コモン・アンコモンは偏光なし（差が分かるように）。
   - 画像生成に頼らず、CSS（`conic-gradient`・`mix-blend-mode`・`background-position` を傾きで動かす）と、必要ならホロ用のマスク画像・きらめきの画像で作る。重くしない（同時に動く偏光は画面内のカードだけ。`IntersectionObserver` で画面外は止める）。「動きを減らす」設定（`accessibility.css`・`UI_CONFIG.reducedMotion`）のときは、動かさず静止した光沢だけにする。
   - 手札・合成・ごほうびのカード演出・図鑑にも、同じ偏光を使い回す（一貫したデザインにする）。
6. **カードの追加・削除の手応え**：追加するときカードが帯へ飛ぶ、削除は帯から落ちる。レアリティが高いほど派手に（音も `Sound.js` に足す）。コストが範囲に入った瞬間に小さく祝う演出。長すぎず、タップで飛ばせる。
7. **デッキの管理**：複数のデッキ枠（3〜5個）に名前をつけて保存・切り替え・複製・削除（`DeckStore.js` を拡張。`localStorage` は try/catch）。見本のデッキ（`decks.json` の `costDeck: true`）から読み込める。「おすすめで埋める」ボタン（足りないコストを、今のデッキの傾向に合う安いカードで埋めるのはロジックを変えずに UI 側の簡単な処理でよい）。
8. **使う場所とのつなぎ**：タイトル「デッキ編成」、「ひとりで遊ぶ／同じ端末」の詳細設定（`LocalSetup.js`）、オンラインの部屋の席（`RoomView.js`）で、**選んだデッキの中身がカードの帯でプレビューされる**。決まりに合わないデッキは選べず、直す画面にすぐ行ける。保存したデッキはサーバーへ `setSeat` の `deckList`（`{種類: 枚数}`）で送る（`RoomView.useMyDeck`）。
9. スマホ縦（390×844・360×640）が基準。PC でも崩れない。タップしやすい大きさ（最小44px）、キーボード・スクリーンリーダーでも操作できる（`aria`、フォーカス順）。色だけで区別しない（レアリティは色＋記号）。

## B. 全体のデザインと UI の見直し

今の画面は、後から足した CSS（`style.css`・`theme.css`・`step5.css`・`polish.css`・`layout.css`・`kingdom.css`・`materials.css`・`card-base.css` …）が何枚も重なっていて、見た目も部品もばらばら。**1つのデザインとして整理し直す。**

1. **デザインの決まりを作る**：色・角丸・影・フォント・余白・ボタン・パネル・バッジ・ゲージの「部品の一覧」を CSS 変数と共通クラスにまとめ（`css/tokens.css` など）、画面ごとの上書きを減らす。重なった CSS は、見た目を変えずに整理できるものから統合する（消すときは影響を確かめる）。`docs/` に短いデザインメモ（部品の使い方・色・余白の表）を書く。
2. **画面ごとの見直し**（それぞれ、初めての人が説明なしで分かるか・待ち時間が短いかを点検）：
   - タイトル（最初の1分で面白さが伝わる。長い説明から始めない）
   - 対戦の盤面（上のバー・城・道・兵士・魔物・手札・ボタンの配置と大きさ、情報の優先順位。天候バッジ・MP・コイン・チャットボタンが混み合わないように）
   - 手札（カードの見た目の統一、出せない理由の出し方、合成できるペアの印、レアリティの偏光）
   - 部屋・ひとりで遊ぶの設定、設定画面、図鑑・排出率、遊び方、強化（ショップ）、結果画面（再戦までの操作を短く）、チュートリアル
3. **一貫したアニメーション**：画面の出入り・ボタン・数字・ゲージ・カードの動きに、共通の「動きの決まり」（速さ・イージング。`UI_CONFIG.timing` と CSS 変数）を作る。桜井流：攻撃が当たったらヒットストップ・揺れ・大きな数字をセットで、強いほど大きく。演出は全部タップで飛ばせる。1回の演出は目安2秒以内。
4. **今回入った機能の仕上げ**
   - 天候：7種類それぞれのアイコン（`assets/ui/`）、背景の効果の作り込み（雨・雷・霧・砂嵐・コイン・晴れの光）、**変化の警報演出**（サイレンの音・赤い縁・帯・画面の揺れ。良い天候は金、雨は青）、天候バッジの説明（タップで効果と残り周回）。天候の呪文カードの絵。
   - 魔物の駒：魔物の絵の使い回しをやめ、**兵士カードとしての専用の枠・絵（12種）**と、手札に入った瞬間の演出（ごほうびのカードとは別に1枚増えることが分かるように）。盤面での見た目も魔物の仲間だと分かるように。
   - 体力ゲージ：兵士・魔物・城のゲージの見た目を統一（減ると色が変わる・白い影が追いかける。小さくても読める）。
   - チャット・スタンプ：スタンプの絵（絵文字ではなく、`assets/STYLE.md` の絵柄の**キャラクター付きスタンプ12種**。`data/stamps.json` の `id` と同じファイル名にして、`icon`（絵文字）は絵が読み込めないときの代わりにする）、吹き出しのデザイン、通知、スマホでキーボードが出ても崩れない配置。
   - 画面の揺れ：強さの段階を点検（小さなダメージで酔わない・大きな攻撃は派手に）。設定の「動きを減らす」で止まる。
5. **自分で足りないものを見つけて作る（必須）**：一通り遊び（ひとりで・3人以上の広場・チーム戦・オンライン・天候あり）、分かりにくい・足りない・うるさい・遅い所を洗い出して直す。足したものは PR に書く。

## 画像・アニメーション・音の作り方

- 絵は `assets/STYLE.md` の「共通の指示文」を毎回付けて作る（画像生成 AI）。背景透明の PNG、1枚 300KB 以下、ファイル名は小文字の英字とハイフン。**作者・絵柄がばらばらの素材を混ぜない**。出どころ（道具名）・ライセンス・作った日を、同じPRで `assets/CREDITS.md` に書く。再配布禁止の素材は入れない。
- 必要な素材の例：天候アイコン7・天候の呪文のカード絵・スタンプ12・魔物の駒の枠と絵12・デッキ編成の背景・カードの偏光用マスク／きらめき・デッキ枠の飾り・コストの宝石（5色）・ボタン／パネルの部品・合成やごほうびの演出用の光・粒子。
- アニメーションは、CSS（`@keyframes`）か Web Animations API（`Animations.js` の `animate()` を通す。skip・動きを減らすに従うため）で作る。スプライトシートを作るなら 1シート 300KB 以下。
- 音は `js/ui/Sound.js`（WebAudio）に足す。外部の音源を使うなら、再配布できるライセンスだけを使い `CREDITS.md` に書く。
- 読み込みが重くならないように：新しい画像は `js/ui/art.js` の読み込み一覧（プリロード）に足し、`precache.js` を作り直す。起動時に全部を読まない。

## 進め方（PR を分ける。1つずつ、レビューを受けてから次へ）

1. デザインの決まり（トークン・共通部品・動きの決まり）と、`docs/` のデザインメモ
2. デッキ編成画面（A のすべて。偏光を含む）
3. 対戦の盤面・手札・結果画面の見直し（体力ゲージ・揺れの調整を含む）
4. 天候（アイコン・背景の効果・警報演出）
5. 魔物の駒（枠・絵・入手演出）
6. チャット・スタンプ（絵・吹き出し）
7. タイトル・設定・図鑑・遊び方・ショップ・チュートリアルの見直し

## 守ること（どの PR でも）

- 桜井流：迷ったら「遊ぶ人が楽しいか」。押して何も起きない操作を作らない（出せない理由を出す）。演出はタップで飛ばせる。待ち時間を短く。作った本人は慣れているので、難しさは「思ったより下げて」考える。
- ロジック・数値・`data/` は変えない。UI から Game の状態を直接書き換えない（Game のメソッド、オンラインならクライアント越し）。外部パッケージは使わない（ES Modules）。
- 表示名・チャットの文字・カード名は `textContent` で出す（HTML として入れない）。
- 1つの PR ごとに、**何を作ったか・スクリーンショット（390×844、デッキ編成は偏光の動きが分かる短い動画か連続画像も）・確かめたこと（`node --test`・スモークテスト・自分で遊んだ結果・コンソールにエラーがないこと）・自分で足したもの・ロジック側で必要な変更**を書く。自分の PR を自分でマージしない。
