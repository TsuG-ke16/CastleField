# 情報設計と既存機能の対応

調査した土台はPR #188。PR #189の3D表示・座標復帰修正を画面側のファイルに取り込み、既存の陣営カード・ゲームロジックを保つ。前案PR #190の配色・レイアウトは引き継がない。

| 機能 | 既存コード | 新しい入口 |
|---|---|---|
| 名前・アイコン・称号・レベル・通貨・通知 | Home.render / ProfileView / AccountPanel | 上部のプロフィールと通貨。詳細はアカウントタブ |
| ルールセット | data/modes.json / main.boot | 通常／4陣営の切替。既存データを画面側でロード |
| ソロ・CPUの強さ・任意設定 | Home.onPlay → openPlaySetup → LocalSetup → startLocal | 下部の対戦形式→開始→CPUの強さ |
| カジュアル・合言葉・部屋 | openPlaySetup('online') / RoomView | 対戦形式→開始→合言葉。通常モードの経路を保つ |
| 同じ端末・2〜8人・チーム等 | LocalSetup | 対戦形式→開始→人数等の設定 |
| 使用デッキ・保存枠・コピー・削除・編集 | Home.renderDeck / DeckStore / DeckEditor | 開始CTAの上のデッキ行、デッキタブの管理機能 |
| 4陣営の固定デッキ | Setup.factionDecks / data/factions | デッキ行から陣営を選択。通常のコスト制編集と混同させない |
| シーズン・ランク | Home.renderSeason / setRank / RankedView | 戦場の下の進行行。詳細・ランキングは補助メニュー |
| 図鑑・カード拡大 | CardGuide / CardZoom | デッキタブとホームの補助メニュー |
| フレンド・ランキング・ミッション | SocialView / RankingView / MissionView | ホーム補助メニュー、アカウントタブ |
| ガチャ・1回/10連・価格・ショップ・スキン | CollectionView / Home.renderPulls | ガチャタブ、デッキタブのスキン |
| 設定・遊び方・アカウント管理 | Settings / HelpView / AccountPanel | 設定タブ。遊び方の入口も保つ |

現在の4陣営はデータとローカルエンジンは存在するが、main.bootはcardSetのない陣営定義を読めず、ホームの世界切替にも実際のハンドラーがない。今回、ローカル起動と選択UIを接続する。サーバー側の4陣営対応は別PR #182にあるため、このブランチだけでオンライン対応済みとは表示しない。通常モードのオンライン機能を維持し、陣営モードでは理由を示す。

## 起動から開始まで

- 再訪：記憶した形式とデッキを確認→開始→CPU強さ（または合言葉／同じ端末設定）。
- 形式変更：形式行→選択シート→形式選択→開始。
- デッキ変更：デッキ行→デッキ選択／編集→元の準備画面へ戻る。
- ルール変更：上部の通常／4陣営→データ切替→選択中の陣営を確認→開始。
- 通知・ショップ等：明示した別画面へ。閉じると選択中のタブへ戻る。

## 表示の優先順位

1. 開始CTAと、何を始めるかを示す形式。
2. 選択中のデッキ／陣営。
3. 城を攻め合うことがわかる戦場アート。
4. シーズン・ランク、プレイヤー情報。
5. 図鑑、ランキング、ミッション等の補助機能。

通信待ちでローカル開始を妨げない。未取得の通貨・ランクは仮の成績で埋めない。サーバー未接続でも、ソロ・同じ端末・図鑑・編集・設定が使える。
