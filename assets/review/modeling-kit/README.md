# 4陣営 モデリング・UI素材集

既存の4陣営カードと承認済みフレームを土台にした、最初の3D制作向け素材セット。既存モードの駒や城を一括で置き換える変更ではなく、Blenderで同じ世界観を作るための資料と、UIから使える画像を揃えた。

## 内容

| 素材 | 数 | 用途 |
|---|---:|---|
| 兵士の正面・側面・背面 | 15種・45枚 | 頭身、衣装、装備、乗り物、翼・尾の確認 |
| 城の正面・側面・背面・真上 | 4種・16枚 | 四隅の塔、中央棟、門、屋根、壁の組み立て |
| 陣営章 | 4枚 | 陣営選択、デッキ、対戦者の表示。256×256 |
| フィールド小物 | 8枚 | 踏み石、草、岩、柱、根、紫水晶、かがり火、低い壁 |
| 砂漠ステージ背景 | 1枚 | 576×1024（軽量表示用）。中央はユニットや盤面用に空けた |
| Blenderライブラリ | 1ファイル | 19コレクション・61枚の資料画像を内蔵 |
| Blenderフィールド見本 | 1ファイル | 3レーン×5マスと城の設置範囲。仮形状のみ |

[確認ページ](index.html)はHTTPサーバーから開く。[catalog.json](catalog.json)に各画像のパス、出典、透過輪郭、接地位置、モデルの参考寸法を記録。原本シートは `sources/*.webp` に圧縮して保存している。

ゲームから参照しやすい場所は次のとおり。

- `assets/ui/factions/crest-*.png`：UI用陣営章。[使用例](../../ui/factions/README.md)。
- `assets/castles/castle-faction-*.png`：城の正面。512×512、透過。
- `assets/props/field-*.png`：小物。512×512、透過。
- `assets/bg/stage-desert.png`：砂漠。既存の `Renderer.setStage` がmanifest経由で読み込む。踏み石と入力領域は既存UIが重ねる。
- `assets/review/modeling-kit/units/` と `castles/`：参照用の個別画像。完成したアニメーション付き駒ではない。

個別PNG74枚は各300KB以下。制作資料、Blenderファイル、原本シートはPWAの事前キャッシュ対象から外れる `review/` 配下に置いた。城の損傷段階、モデルのゲームへの接続、アニメーション・リグは次の制作工程。

## デザインの基準

兵士は `data/factions/cards/*.json` の `kind: soldier` 全15種を対応させた。**既存のカード絵を衣装・顔・武器の基準にする**。今回の背面・側面は、そのカード絵から補った造形案。生成図には細かい形や装備角度の揺れがあるので、三方向を別々にトレースせず、同じ1個の立体として整合させる。姿勢はニュートラルな参照姿勢であり、厳密なリグ用A/Tポーズやスキャン図ではない。

城と陣営章はフレームの意匠を引き継ぐ。王国＝銀翼・王冠・青、森＝編み根・琥珀、魔族＝黒鉄・骨・紫水晶、竜族＝黒い竜鋼・金属の角・翼・紅玉。竜族の枠・建築・陣営章には鱗模様を使わない。既存の竜キャラクター自身の身体表現は元カードに従う。

魔法やスキルの主役は効果そのものとする既存の方針を維持する。このセットのキャラクター図は、兵士のモデリング資料としてのみ作成した。

## Blenderで始める

Blender 4.3.2で実際に作成・再読み込みを検証した。画像は `.blend` 内にパック済み。

1. `blender/character-library.blend` を開く。最初は王国歩兵の資料を表示する。
2. アウトライナーで `CF_REF_<カードID>` コレクションを選び、その資料だけ表示する。他の資料は同じ原点に重なるため非表示にする。
3. 足元がZ=0。正面は-Yを向く。**側面の向きは各項目の `profileCamera` を確認する**。通常の兵士は-X側から見た図、竜騎兵と城は+X側から見た図になっている。図を左右反転して装備位置を入れ替えない。
4. 参照画像は選択ロック済み。別コレクションにメッシュを作る。リグは `root` を足元に置き、武器・盾・マント・翼・尾は別部品で制作する。
5. フィールドは `blender/field-template.blend` を開き、仮形状を配置位置の目安として、自作の地面・石・城へ差し替える。

既存のBlenderシーンへ資料を追加する場合は、テキストエディターで `blender/setup_references.py` を実行する。既定では歩兵1種を追加し、既存オブジェクトを削除しない。別の資料は末尾の `main()` を呼ぶ前に引数を指定するか、次のCLIを使う。

```sh
blender --background --python assets/review/modeling-kit/blender/setup_references.py -- --asset fac_forest_elf --save /tmp/elf-reference.blend
blender --background --python assets/review/modeling-kit/blender/setup_references.py -- --all --save /tmp/all-references.blend
blender --background --python assets/review/modeling-kit/blender/setup_references.py -- --field --save /tmp/field.blend
```

`--factory-empty` は**空の新規ファイルを作るCLI処理専用**。この明示オプションを付けた場合だけ既存シーンをリセットする。普段の追加読み込みには付けない。Unit Scale=1が前提で、別の単位設定ならスクリプトが停止する。

## フィールドの制作寸法

[field-layout.svg](field-layout.svg) と `catalog.json` の `field` が今回の仮配置。**メートル単位の制作案で、ゲームルールの変更ではない**。3レーン・各5マスは現在の4陣営ルールに対応させた。

| 項目 | 制作上の目安 |
|---|---|
| 地面 | 幅12m × 奥行20m、Z=0 |
| レーン中心 | X=-2.4 / 0 / +2.4m |
| 各マス中心 | Y=-4 / -2 / 0 / +2 / +4m |
| 踏み石 | 半径0.8m。装飾で歩ける上面を埋めない |
| 城の中心 | (0,-7.2,0) / (0,+7.2,0)、設置範囲4.8m四方 |
| 城の向き | 下側の城は+Y、上側の城は-Yへ門を向ける |
| 高い装飾 | 原則として左右の外周、中心がXの絶対値4.2m以上 |

中央の3つの石を強調しているのは配置の見分け用で、新しい共通広場や範囲効果の仕様ではない。踏み石・草・岩を繰り返し使い、陣営固有の根・紫水晶・かがり火・壁は外側へ置く。小物はタイル状に繰り返せるシームレス画像ではなく、立体を作るための単体見本。

## 作る順番と部品の分け方

まず王国歩兵と踏み石で、ゲーム画面に近い縮小表示の読みやすさを確認する。次に王国の他4兵種を共通の人型素体から制作。森・魔族の人型、騎兵と竜騎兵の乗り物、幼竜2種の順に進めると、共有できる部品を増やしやすい。

城は土台・四隅の塔・壁・中央棟・門・屋根・陣営章を別部品にする。将来の損傷表示に備え、壁や屋根を一体の大きなメッシュにしない。門の開口は幅1.8m・高さ2.6m程度を目安にし、乗り物の通過を確認する。木の枝や翼の見せ場は、近隣レーンの兵士を隠さない幅に調整する。

## 軽量化・出力の目安

- 兵士2,000〜5,000三角形、城6,000〜12,000、小物100〜1,000程度から始める。これは初期の制作目標で、現在の描画エンジンの上限ではない。
- 人型の基本アニメーションは待機・移動・攻撃・被弾・退場。乗り手と乗り物は別リグで、座席ソケットで接続する。幼竜2種は胴体・翼・尾の基本リグを共有できる。
- 1モデル1〜2マテリアルを目安にする。兵士の色はカード絵に合わせ、席の青・オレンジは独立した足元リングや旗で示す。陣営の色と席色を混同しない。
- GLB出力前にスケールを適用し、足元の原点・法線・透明部分・影を確認。初期は1024pxの共有テクスチャを試し、遠景で消える細かな模様へ容量を使いすぎない。
- カードのフレームは既存の [表裏接続ガイド](../faction-frames/README.md) を参照。このキャラクター・フィールド資料はZ-up、カード資料はY-upなので、座標規約を混ぜない。

原画をそのまま高さマップ・法線マップにする処理は含めていない。完成モデルへUVを展開してから、実際の形状に合わせてテクスチャをベイクする。
